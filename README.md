## Architecture that explains its choices

I frame the problem, define system boundaries and document the trade-offs behind an approach. A useful architecture gives its operators a clear path to understand dependencies, failure modes and recovery.

## Automation with explicit controls

I turn repeatable work into documented workflows, including AI-assisted workflows where they add value. Inputs, permissions, human decisions and stop conditions should be clear before automation acts.

## Delivery that can be checked

I value reproducible setup, targeted tests and evidence that matches the claim. A delivery should explain how to run it, how to verify it, what remains untested and how to recover when a change fails.

## What I look for in a technical handoff

- A concise problem statement and a clear scope.
- Setup and verification steps another person can follow.
- Tests or concrete checks for the behavior being claimed.
- Documented limits, dependencies and recovery steps.
- Examples that protect credentials and sensitive information.
